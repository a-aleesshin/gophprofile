# Локальная разработка

Стенд поднимается через Docker Compose: два сервиса, их зависимости и полный
набор наблюдаемости. Развёртывание в Kubernetes описано в
[DEPLOYMENT.md](DEPLOYMENT.md).

## Запуск

Требуется Docker и свободный порт 8000.

Первым делом локальная конфигурация:

```bash
task env
```

Команда делает два файла из примеров рядом с ними: `.env` для compose и
`deploy/helm/gophprofile/values-local.yaml` для чарта. Оба лежат в `.gitignore`,
в репозиторий попадают только примеры. Четыре секрета в `.env` генерируются,
учётные данные стенда подставляются в values из `.env`.

Без секретов compose не стартует, и это сделано намеренно: пустой секрет
подписи хуже отсутствующего, потому что выглядит как работающая подпись.
Существующие файлы команда не изменяет.

Поднимите стенд:

```bash
docker compose up -d --build
```

Первый запуск занимает несколько минут: собираются два образа и поднимаются
двадцать четыре контейнера. Шесть из них одноразовые — миграции, создание
бакета, топиков, шаблона индекса и каталогов для трейсов. Остальные
восемнадцать работают постоянно.

Стенд требователен к памяти: кроме двух сервисов и их зависимостей
поднимается весь набор наблюдаемости, и больше всего её запрашивает
OpenSearch — по умолчанию 512 МБ хевпа (`OPENSEARCH_HEAP` в `.env`). Если
Docker ограничен парой гигабайт, начните с этой настройки.

Когда стенд поднимется, откройте **http://localhost:8000**. Там консоль со
всеми возможностями сервиса: загрузка, галерея, привязка email, три вида
ссылок и удаление. Каждый запрос она записывает в журнал, поэтому видно, из
чего складывается загрузка.

Остановите:

```bash
docker compose down
```

Удалите вместе с данными:

```bash
docker compose down -v
```

## Команды

```bash
task env                # создать .env, если его ещё нет
task test               # юнит-тесты
task test:integration   # тесты с настоящими Postgres, MinIO, Rabbit и Kafka
task lint               # golangci-lint
task up / task down     # то же, что docker compose
task --list             # все команды
```

Интеграционные тесты поднимают контейнеры самостоятельно через testcontainers,
заранее запускать ничего не нужно. Им нужно место на диске Docker: если
Postgres падает с `No space left on device`, помогает `docker builder prune`.

## Наблюдаемость стенда

| Куда смотреть | Адрес | Что там |
|---|---|---|
| Grafana | http://localhost:3000 | три дашборда: обзор, ресурсы, бизнес |
| Jaeger | http://localhost:16686 | трейс одного запроса целиком |
| OpenSearch Dashboards | http://localhost:5601 | поиск по логам всех сервисов |
| Prometheus | http://localhost:9090 | сырые метрики и состояние правил |
| Alertmanager | http://localhost:9093 | что сейчас горит |

Авторизация не требуется: в Grafana включён анонимный вход с правами чтения.

Алерты уходят вебхуком в контейнер `alert-sink`, который печатает их в свой
лог:

```bash
docker compose logs -f alert-sink
```
