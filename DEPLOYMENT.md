# Развёртывание в Kubernetes

Сервисы разворачиваются Helm-чартом из `deploy/helm/gophprofile`. Требуется
кластер с поддержкой сервисов типа LoadBalancer; локально подходит Kubernetes
из Docker Desktop. Локальный стенд на Docker Compose описан в
[DEVELOPMENT.md](DEVELOPMENT.md).

## Порядок установки

Сначала то, что чарт ожидает найти в кластере: ingress-контроллер,
metrics-server для автомасштабирования, Prometheus с Grafana и Alertmanager,
Jaeger для трейсов, Loki с Fluent Bit для логов.

```bash
task k8s:cluster
```

Затем базы, хранилище и брокеры:

```bash
task k8s:deps
```

Затем сборка образов и установка чарта:

```bash
task k8s:up
```

Команда помечает образы sha коммита и передаёт в чарт секреты из `.env`. После
установки консоль доступна по адресу **http://localhost:8080**, там же API,
раздача содержимого и загрузка в хранилище.

Удалить релиз:

```bash
task k8s:down
```

Удалить вместе с зависимостями и данными:

```bash
task k8s:down:clean
```

## Что входит в чарт

| Объект | Назначение |
|---|---|
| Deployment ×5 | два сервера, два воркера, консоль |
| Service | именованные порты `http`, `grpc`, `health`, `metrics` |
| Ingress ×4 | консоль, API, раздача содержимого, загрузка в хранилище |
| ConfigMap и Secret | настройки и секреты каждого сервиса |
| Job | миграции, хуком `pre-install` и `pre-upgrade` |
| HPA | серверы масштабируются по загрузке процессора |
| PodDisruptionBudget | при вытеснении узла уезжает не больше одного пода |
| NetworkPolicy ×6 | запрет всего по умолчанию и шесть разрешений |
| ServiceAccount | один на релиз, токен не монтируется |
| ServiceMonitor | оператор Prometheus находит и собирает метрики |
| PrometheusRule | одиннадцать правил алертов |
| ConfigMap с дашбордами | три дашборда Grafana |

Правила алертов и дашборды лежат в чарте, в каталоге `files/`. Их же читает
Docker Compose, поэтому определение одно на оба способа запуска.

## Окружения

`values.yaml` задаёт структуру и значения по умолчанию. `values-local.yaml`
добавляет адреса и секреты стенда. `values-prod.yaml` описывает продакшн: три
реплики с автомасштабированием, включённый трейсинг, TLS на Ingress и секреты
из заранее созданных объектов кластера.

Тег образа задаётся при установке, значения по умолчанию у него нет. Это
сделано намеренно: узел кеширует образ по тегу и не перечитывает его при
пересборке, поэтому неизменяемый тег на каждую сборку — единственный способ
гарантировать, что в кластере работает ожидаемый код.

## Устойчивость

**Остановка.** У подов `terminationGracePeriodSeconds: 30` и `preStop` на пять
секунд. Пять секунд уходят на то, чтобы под успел покинуть endpoints до начала
остановки, затем сервис дорабатывает начатые запросы и завершается сам.

**Пробы.** Readiness проверяет базу и при её недоступности уводит под из
балансировки. Liveness зависимости не проверяет и процесс не перезапускает:
упавшая база — не повод убивать приложение.

**Автомасштабирование.** HPA стоит только на серверах. Воркеры масштабируются
глубиной очереди, а не процессором, и для этого нужны внешние метрики.

## Безопасность

Контейнеры запускаются не от root, с файловой системой только для чтения и без
дополнительных capabilities. ServiceAccount один на релиз, токен не монтируется.

NetworkPolicy запрещает весь трафик по умолчанию и открывает шесть направлений:
DNS, вход с ingress-контроллера на `http`, вход на `grpc` у `file` только от
сервера и воркера `profile`, сбор метрик из namespace мониторинга, выход к
зависимостям и выход к коллектору трейсов.

Конфиденциальные значения — строки подключения, токены и ключи хранилища —
лежат в Secret. В ConfigMap остаются только адреса и лимиты.
